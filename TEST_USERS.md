# Тестовые пользователи Selena Znaju

Миграция `identity.0008_create_development_test_users` создаёт два тестовых аккаунта **только когда `DEBUG=True`** (в проекте это `manager.settings.dev`).

| Роль | Логин | Пароль по умолчанию |
| --- | --- | --- |
| Администратор | `root@mail.ru` | `SelenaAdmin-2026!` |
| Пользователь | `user@mail.ru` | `SelenaUser-2026!` |

Параметры `SELENA_TEST_ADMIN_PASSWORD` и `SELENA_TEST_USER_PASSWORD` можно заменить в корневом `.env` **до первого применения** миграции.

Миграция записывает только хеши паролей Django, использует `get_or_create`, восстанавливает отключённые ранее тестовые пароли, но **не меняет уже работающий пароль** существующего аккаунта. Повторное применение миграций не приводит к созданию дублей.

Эти пароли являются публичными тестовыми значениями. Не используй их в production и не публикуй dev-окружение в интернет. В `prod` миграция отмечается применённой, но аккаунты не создаёт.

Обнови ветку и запусти:

```bash
git pull origin create-catalog
docker compose up -d --build
docker compose logs db-init
```

Если миграция уже применена к существующей базе и там был пользователь с установленным паролем, его пароль сохранится. В таком случае используй существующий пароль или поменяй его отдельно.
